# Windows ログイン補助の検証

対象は Windows 11 / x64。自動入力は検証用 Windows PC の対話セッションで、ダミーの ID・パスワードだけを使って検証する。SSH からのオフラインスモークテストでは画面・入力操作を実行しない。

## 実装済みの停止条件

現在のRiotクライアントは Electron（`RiotClientElectron\Riot Client.exe`、`Chrome_WidgetWin_1`）で、UI Automation ではウィンドウ内の要素が0件になる（2026-09-21 実機確認）。入力欄は UI Automation ではなく、登録した位置と画素の照合で扱う。

- 設定された RiotClientServices.exe と同じインストール配下にある `Riot Client`（旧 `RiotClientUx`）の、可視のトップレベルウィンドウを選ぶ。複数ある場合は中止する。
- 前面ウィンドウの変更をイベント監視し、一度でも対象から離れたら再開しない。
- 文字ごとにキャンセル・Esc・対象プロセス・ウィンドウ所有 PID・可視/有効状態・位置・サイズ・DPI・前面ウィンドウ・ネイティブキーボードフォーカス（Riotウィンドウ内であること）を確認する。
- 入力中のマウス移動、修飾キー、Tab、Enter、マウスボタン押下でも中止する。
- 座標はウィンドウ内座標。ログイン操作開始前のウィンドウ移動には対応し、操作途中の移動は中止する。クリック直前に他ウィンドウで隠れていないことを確認する。
- 位置登録（形式 v3）は現在の画面サイズ・DPI・クライアントバージョンと、各欄の中心点・検査帯（欄幅程度×欄高の約半分、DPI 換算）に紐づく。旧形式（v2）の登録は使わず、再登録が必要。
- ログイン時は、各欄の登録点をクリックした後、検査帯が登録時の「空でフォーカスした状態」と一致することを要求する（変化した列がキャレット程度＝96dpiで3列以下）。一文字でも残っていれば中止する。フォーカス枠は検査帯の外側にある。
- 入力後に検査帯が文字数に応じて変化したこと（96dpiで 4＋文字数（上限8）列以上）を確認できなければ、送信せずに中止する。ID・パスワードとも値は読まない。
- 送信はパスワード欄で Enter を押す。ログインボタンは識別・クリックしない。
- Windows が SendInput を受け付けない場合は中止する。ID やパスワードに改行・制御文字は許可しない。

### 従来（UI Automation 方式）からの変更点と残るリスク

UI Automation で確認していた「同じ編集欄にフォーカスがある」「パスワード属性である」「送信ボタンを識別する」検査は行わなくなった。代わりに、画素の照合（登録時の空の状態との一致と、入力後の変化）で確認する。次の点で従来より弱い。

- 検査帯が一致しても、それが本当にパスワード欄であることは意味的には保証されない。ページ構成が登録時と同一に見える別の画面では、誤った欄へ入力しうる（ウィンドウ内に限られる）。
- 背景のアニメーション、入力欄の見た目の変更（クライアント更新）、テーマ変更は、照合失敗（安全側の中止）を起こしうる。その場合は位置を登録し直す。
- 入力の確認は、検査帯の画素が変化したことだけを見る。入力欄以外の場所へ入力された場合の検知は、検査帯の変化がないことによる。

## 位置登録の前提

自動入力の案内画面で利用者が ID・パスワードの両方を空にしたことを確認してから開始する。パスワード欄は値を公開しないため、空欄の初回確認は利用者の確認と登録時の画素に依存する。登録画像は各欄の検査帯だけを切り出し、DPAPI で暗号化して保存する。

位置登録の後は「試験入力を確認する」（ダミー文字の入力と消去、送信なし）で、実際に文字が入ることを確認する。確認できない場合は秘密情報を入力せず、個別コピーを案内する。

## 対話セッションでの実機チェックリスト

| 項目 | 操作・期待結果 | 状態 |
| --- | --- | --- |
| クライアント検出 | `Riot Client` の可視ウィンドウを検出する（Riotが未起動でも起動して待つ）。複数ウィンドウは中止 | 未実施 |
| 位置登録 | 空欄確認後 F8 で ID、パスワードの順に登録する。逆順・近すぎる欄・画面外・隠れた位置を拒否する | 未実施 |
| 試験入力 | ダミー文字が両欄に入り、消去後に空へ戻る。送信はしない。文字が入らない位置では「確認できなかった」で止まる | 未実施 |
| 空欄画像 | 同じ表示状態で受理し、入力欄の一文字・パスワードの一個のマスク表示・配置変更を拒否する（キャレットは許容） | 未実施 |
| 移動 | 開始前のウィンドウ移動では登録を利用でき、入力途中の移動で残りの入力と送信を中止する | 未実施 |
| DPI / サイズ | 100%→125% の画面移動、サイズ変更、バージョン不一致で再登録を求める | 未実施 |
| 別画面へのフォーカス | 入力途中で別アプリへ切替。元に戻しても残りの入力・送信が再開しない | 未実施 |
| 同一画面内フォーカス | 入力途中でRiot内の別の場所をクリックした場合、残りの入力・送信を中止する（マウス移動で中止） | 未実施 |
| 中止操作 | Esc、キャンセル、マウス移動、Tab、修飾キーで中止し、キー押下状態を残さない | 未実施 |
| 対象消失・重なり | クライアント終了・再作成・モーダル画面・別ウィンドウの重なりで中止する | 未実施 |
| 送信表示 | ダミーフォームの送信操作後も「認証成功は未確認」と表示する。実アカウント認証や追加認証を自動化しない | 未実施 |
| 権限差 | 通常権限と管理者権限の不一致による SendInput 拒否をエラー表示する | 未実施 |

SendInput は対象 HWND を指定する API ではない。各文字の直前確認とイベント監視は実装しているが、確認と OS による入力処理の間の競合を完全に排除することはできない。入力中は他の操作を避ける。入力は送信完了までで、認証成功の判定は行わない。

仕様参照: [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)、[GetGUIThreadInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo)。

## 案内式設定の追加チェック（Windows実機：未実施）

- クライアント検出済みなら場所をそのまま使え、未検出・不正パスならファイル選択で修正できる。
- 「次へ」でパスを保存し、戻った画面でも保持する。APIキーの未保存変更がある場合は案内への移動前に保存を促す。
- クライアントを開いた後はRiotを前面に保ち、利用者がログアウト・空欄化できる。
- 空欄確認なしでは画面確認・位置登録を開始できない。画面確認では資格情報の取得・入力・送信をしない。
- 登録済みの位置がいまの画面で有効なら位置登録を省略し、未登録・不一致なら位置登録の案内を示す。
- 登録中は1/2〜2/2の案内を表示し、Riotのフォーカスを奪わない。案内が対象欄に重なる場合も安全確認を回避しない。
- Esc・途中終了・検証失敗で以前の登録を保持し、空欄確認から最初から再試行できる。
- 処理中の連打・閉じるで二重操作や閉じた画面への進捗通知が発生しない。
- 100% / 125% / 150%の表示倍率でボタン・説明が読め、スクロールで全操作に到達できる。
- 完了表示は認証成功を意味せず、個別コピーの案内からアカウント画面へ戻れる。
